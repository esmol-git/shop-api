# ADR 0001: Жизненный цикл товара — архивация vs физическое удаление

## Контекст

У товара появляются складские движения и ключи идемпотентности. Безусловный
`DELETE /products/:id` уничтожил бы защиту от повторов и след операций.
`ON DELETE CASCADE` для движений неприемлем: история и ключи должны
переживать уход товара из витрины.

Между «посчитать движения» и «удалить» возможна гонка: новая операция
успеет записаться. Запрет удаления нельзя строить только на предварительном
подсчёте без атомарной проверки.

## Решение

Два явных действия:

1. **Архивация** — `POST /products/:id/archive`
   - сохраняет товар, движения и ключи;
   - не обнуляет остаток и не отключает учёт;
   - исключает товар из обычного списка каталога;
   - повтор для уже архивного → `204`.

2. **Физическое удаление** — `DELETE /products/:id`
   - только если нет истории движений **и** остаток `null` или `0`;
   - выполняется атомарно (условие в `DELETE … WHERE … AND NOT EXISTS`);
   - положительный остаток или история → `409` с разным смыслом.

Восстановление из архива в этом срезе **не** делаем.

Складские команды для архивного товара пока **не** запрещаем автоматически:
иначе архив с остатком лишит способа корректно списать. Правила чтения
архива администратором и ограничения склада уточним отдельно; сейчас
`GET /products/:id` возвращает и архивный товар (с `archivedAt`).

Будущие заказы и резервы добавят свои запреты на удаление — направление
то же: нельзя терять историю и удержанный товар.

## HTTP-контракт

### `DELETE /products/:id`

| Состояние | Ответ |
|---|---|
| Товара нет | `404` «Товар не найден» |
| Нет движений, остаток `null` или `0` | `204`, строка удалена |
| Есть складские движения | `409` «Товар имеет историю складских операций; используйте архивацию» |
| Остаток положительный | `409` «Нельзя удалить товар с положительным остатком» |

### `POST /products/:id/archive`

| Состояние | Ответ |
|---|---|
| Товара нет | `404` |
| Активный товар | `204`, выставлен `archivedAt` |
| Уже архивный | `204` (повтор) |

`GET /products` — только неархивные. `total` считается по той же выборке.

## Последствия

- Признак архива: `products.archivedAt` (`timestamptz`, null = активен).
- Фильтрация каталога по `archivedAt IS NULL`.
- История и ключи при архивации сохраняются.
- **Срез 6 (сделано):** FK `stock_movements.productId → products.id`
  с `ON DELETE RESTRICT` / `ON UPDATE RESTRICT` и индекс по `productId` —
  окончательная защита целостности; не `CASCADE`.
