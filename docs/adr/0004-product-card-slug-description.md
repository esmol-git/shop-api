# ADR 0004: Карточка товара — description и slug

## Контекст

Каталогу нужны текст описания и стабильный человекочитаемый идентификатор
для URL. Это поля `Product`, без новых связей и без смены DELETE/archive.

## Решение

| Поле | Правило |
|---|---|
| `description` | опционально; trim; пустая строка → `null`; max 5000 |
| `slug` | обязателен, уникален; `^[a-z0-9]+(?:-[a-z0-9]+)*$`; 1–100 |

### Create

- `slug` можно не передавать.
- Если не передан: `base` из имени (транслит RU→latin + slugify);
  если `base` пуст — сразу `product-{8 hex от id}`;
  если `base` занят — retry с `product-{8 hex от id}` (без счётчиков `-2`, `-3`).
- `409` «Slug уже занят» — только при явной передаче занятого slug.

### PATCH `/products/:id/details`

- Можно изменить `description`, `slug` или оба.
- Успех всегда: `200` + актуальное тело товара.
- Пустое тело и совпадающий текущий slug — успешный no-op (`200` + текущее тело).
- Занятый явно переданный slug → `409`; невалидные поля → `400`; нет товара → `404`.

### Прочее

- Rename (`PATCH /products/:id`) не меняет slug автоматически.
- Существующие строки: backfill в миграции из имени с fallback
  `product-{8 hex от id}`, затем `NOT NULL` + UNIQUE.
- Редиректы старых URL — вне среза.

## Последствия

- Клиент всегда видит финальные `slug` и `description` после details.
- CI-гейт должен оставаться зелёным после миграции.
