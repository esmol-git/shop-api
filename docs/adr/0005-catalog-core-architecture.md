# ADR 0005: Архитектура ядра каталога

## Контекст

Нужно переиспользуемое ядро каталога: сущности, связи, операции, HTTP-контракты,
правила целостности и механизмы выдачи. Конкретный магазин задаёт категории,
бренды и ассортимент **как данные**, без микросервисов, плагинов и
мультитенантности. Доменная карта — примеры и проверочные сценарии, не блокер
кода.

## Решение

### Сущности первой версии

| Сущность | Назначение |
|---|---|
| `Product` | Продаваемая позиция (уже есть) |
| `Category` | Общая классификация; дерево |
| `Brand` | Марка продажи |
| `Manufacturer` | Изготовитель, независимо от бренда |

Линейка/серия, характеристики, фасеты, варианты — **не** вводим сейчас.

### Разделение ролей

- Категория — тип товара (`Телефоны`), общая для брендов.
- Бренд/производитель — отдельные необязательные связи с товаром, **не** узлы
  дерева категорий.
- Навигация — представление выборок; идентичность товара — `/products/{slug}`.

Пример: «Кессоны Дочиста» = категория «Кессоны» + бренд/производитель, а не
вложенный узел «Дочиста» в дереве категорий.

### Категории

- Дерево: один необязательный родитель; циклы и self-parent запрещены.
- Корень = уровень 1; max глубина v1 = **4** (настройка приложения, не
  колонки `level1…level4`).
- Перенос проверяет глубину всего поддерева (срез B).
- Удаление запрещено при детях или прямых привязках товаров, **включая
  архивные** (срез B).
- К нелистовой категории можно привязать товар.
- Уменьшение лимита глубины на заполненной базе — отдельная проверка дерева.

### Привязки Product ↔ Category

- M2M; без привязок основной нет; при ≥1 — ровно одна основная ∈ набора.
- Отвязка основной при оставшихся — только с явной новой основной.
- Родительская страница: товары поддерева без дублей.

### Brand / Manufacturer

- Не более одного бренда и одного изготовителя на товар; оба необязательны;
  независимы.
- Удаление используемого → 409; смена не меняет категории.

### URL и крошки

- Карточка: `/products/{slug}`; категория/бренд не встраиваются в адрес.
- Основные крошки — по основной категории; без неё: Каталог → Товар.
- Страницы бренда и «категория + бренд» — свои цепочки; произвольный редактор
  меню не создаём.

### Очередь срезов

| Срез | Содержание |
|---|---|
| A | Основа категорий: create/read/rename, дерево |
| B | Перенос, удаление, глубина/циклы при конкуренции |
| C | Привязки товара, основная, отвязка |
| D | Бренды |
| E | Производители |
| F | Выдача: поддерево, бренд/изготовитель, сортировка, пагинация |
| G | Навигационный API: крошки и контекстные страницы |

## Последствия

- Срезы вертикальные: ADR → контракт → миграция → код → unit+e2e → `npm run ci`.
- Таблицы «про запас» и универсальное типизированное дерево не создаём.
- К обсуждению «всё сделать категориями» без нового требования не возвращаемся.
