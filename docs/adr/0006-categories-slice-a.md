# ADR 0006: Срез A — основа категорий

## Контекст

Первый вертикальный срез ядра каталога (см. ADR 0005): категории без переноса
и удаления. Нужны create/read/rename и чтение дерева с лимитом глубины.

## Решение

### Модель

| Поле | Правило |
|---|---|
| `id` | UUID |
| `name` | trim, непустое, max 200 |
| `slug` | обязателен при create, явный; unique глобально; **trim + lowercase**, затем формат `^[a-z0-9]+(?:-[a-z0-9]+)*$` и уникальность |
| `parentId` | опционален; UUID **v4** (как у Product); null/отсутствие — корень |
| `createdAt` / `updatedAt` | как у Product |

- Slug после создания **не** меняем в этом срезе.
- Автогенерацию slug из имени **не** переносим из Product.
- Max глубина v1 = **константа** `CATEGORY_MAX_DEPTH = 4` (корень = 1).  
  Уточнение к идее «настройки приложения»: в срезе A **не** выносим в env;
  одна константа, не от клиента. Смена лимита на заполненной базе — отдельная проверка.
- Превышение глубины при create → **409**.
- Занятый slug → **409**.

### HTTP

| Операция | Ответ |
|---|---|
| `POST /categories` | 201 + категория |
| `GET /categories` | 200 + плоский список с `parentId` (**целиком**, лимит v1) |
| `GET /categories/tree` | 200 + вложенное дерево (**целиком**, лимит v1) |
| `GET /categories/:id` | 200 / 404 |
| `PATCH /categories/:id` | 200 + актуальная категория |

`PATCH` принимает только `name` (неизвестные поля → 400, глобально).

| Тело | Поведение |
|---|---|
| `{}` | 200 no-op для существующей; без `update`, `updatedAt` не меняется |
| `{ "name": " Текущее " }` | 200 no-op после нормализации |
| `{ "name": null }` / `""` / `"   "` | 400 |
| нет категории | 404 даже для `{}` |

Порядок выдачи: **`name ASC, id ASC`** в `findAll`; дерево сохраняет этот порядок.

Ошибки: невалидное тело/UUID → 400; нет категории/родителя → 404;
slug занят / глубина → 409.

### БД и граница гарантий

| Инвариант | Защита |
|---|---|
| Уникальный slug | UNIQUE + HTTP-маппинг P2002 только `categories_slug_key` |
| Существующий родитель | FK RESTRICT + HTTP-маппинг P2003 только `categories_parentId_fkey` |
| Нет self-parent | CHECK `parentId IS NULL OR parentId <> id` |
| Максимальная глубина | проверки приложения |
| Нет многоузловых циклов | алгоритм изменения дерева (срез B) |
| Допустимые поля PATCH | HTTP-валидация |

Прямой SQL не считается безопасным способом менять дерево, если межстрочные
инварианты (глубина, циклы) обеспечивает приложение.

### Конкурентное переименование (ограничение A)

Параллельные `PATCH` одной категории **без** optimistic lock / версии:
побеждает последняя успешная запись (`updatedAt` и `name` от неё).
Это не баг текущего контракта — явное ограничение до отдельного требования.

### Вне среза

Перенос, удаление, привязки, смена slug, автогенерация slug,
Serializable/retries — срезы B+ / отдельные ADR.

## Последствия

- Follow-up миграция self-parent CHECK не требует переписывать исходную.
- Регресс Product/склад не допускается.
