# Доменная карта каталога (этап 0)

Статус: **формат принят; карта — примеры и проверочные сценарии, не блокер кода.**  
Выдуманный ассортимент не подставляем как «решённые данные». «Нет» и «не установлено» не смешиваем.  
Slug / URL — только **текущие**. Серии не вводим автоматически.

Архитектура ядра: [ADR 0005](../adr/0005-catalog-core-architecture.md).  
Срез A (категории): [ADR 0006](../adr/0006-categories-slice-a.md).

## Правила заполнения

На каждую карточку:

| Поле | Как заполнять |
|---|---|
| Название | как продаём / как на карточке |
| Текущий slug | из URL/БД; если товара ещё нет в системе — «не установлено» |
| Источник | URL карточки / документ производителя / запись в нашей БД |
| Дата проверки | когда сверяли источник |
| Навигация источника | крошки или разделы **как на исходном сайте** (наблюдение) |
| Предлагаемый основной путь | наша классификация, пока **гипотеза** (не копия чужой навигации) |
| Предлагаемые доп. категории | гипотеза; текущих привязок в нашей системе ещё нет → «нет» / «не установлено» |
| Бренд | марка продажи или «не установлено»; иной источник сведения — рядом |
| Производитель | изготовитель или «не установлено»; иной источник — рядом |
| Серия | только если реально существует; иначе «нет» / «не установлено» |
| Характеристики | см. шаблон ниже: исходное название и значение + предлагаемый тип |
| Фасеты | характеристика → предполагаемый вид фильтра → **основание** |
| Спорное | бренд vs серия, глубина дерева, смешение навигации источника с нашими категориями и т.п. |

Основание фасета — явно одно из: «есть на сайте» | «нужен по нашему требованию» | «гипотеза».  
Наличие свойства в карточке само по себе **не** подтверждает необходимость фильтра.

Навигацию источника **не** превращаем автоматически в узлы нашего дерева (пример: `Главная → Каталог → Юнилос → UNI-SEP` — наблюдение, не готовые категории).

## Кандидат-правила (проверить на выборке)

Не утверждённый ADR — гипотезы для опровержения или подтверждения:

1. Нет привязок → нет основной; есть привязки → ровно одна основная ∈ набора.
2. Отвязка основной при других категориях — только с явной новой основной.
3. Схема характеристик товара = **основная** категория; доп. категории не расширяют схему.
4. Смена основной не должна молча терять значения (правило судьбы значений — отдельное).
5. Товары родителя = поддерево без дублей; фасеты родителя = только настройки **этой** категории.
6. Удаление категории запрещено при детях или **любых** прямых привязках, включая архивные.
7. Max 4 уровня дерева достаточно без искусственных веток.
8. Бренд ≠ производитель ≠ категория; серия не смешивается с брендом без подтверждения.
